# 暂停、恢复与清理

## Session pickup

从本任务卡片/spec、Issue、设计、相关决策记录与已授权历史恢复目标、有效决定、产物/head、证据/缺口、阻塞、授权与下一步；重新核对代码状态、PR/CI 和执行者，各自的事实源裁决实态。旧摘要不能覆盖脏文件与在途 run；不重复建卡、worktree 或唤醒停止者。下一步从真实阶段接续。

## Pause safely

响应用户暂停：保存任务指针、未提交产物、当前 head、在途操作、已验证/缺口与下一步到卡片/spec；只停止本次拥有且允许停止的工作。不要顺手删证据或失败分支，不继续依赖暂停任务派新工作。停止与恢复分别按宿主契约，不把发消息当停止手段。

## Worktree cleanup

先核验交付物合入与当前分支、在途 run、全部适用验证和最新主线门禁；按项目约定的收尾门槛与清理脚本执行。失败、partial、running 或未明确 run 归属时保留载体与说明。不能仅因为交付物已合入、卡片完成或磁盘紧张删 worktree，不能从清理请求推导 merge 授权。
