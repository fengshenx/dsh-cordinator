# 交付、检查与审查

## 开 PR

确认实际 diff、Issue、设计/决策记录、所属消费者文档和行为证据；按项目门禁跑最小检查，风格修复在暂存前。范围用项目自带的变更范围脚本核对，不混入其他任务文件。正常 hooks commit/push，PR 显式指定基线分支并核验基线名；正文解释问题、结果、验收与风险，依赖顺序可见。PR 为交付边界，不自动 approve/merge。

## 盯门禁

收到自动审查评论时先核实来源与当前 head。用户要求的审查由执行者按项目审查规范发布评论/回复/行内意见，是既定收尾，不另索发布许可。读取当前 head、required checks、run/job 状态和审查结论；在途与 partial 不是绿，worker PASS 不是门禁。证据保留在已有交付物或任务简报，字段为 PR、head 哈希、验证层级、验证者、证据指针、缺口，不另建中央台账。核 run 的 head 哈希等于当前 head 且门禁成功；相关验证仍在途或未知不能报全绿，无关自动化不作为通用门槛。失败先核日志、环境与代码根因，授权内修复；持续监控仅用户要求时用宿主 automation。

## 出货

正式审查按项目审查规范执行，多维挑战按专项能力方法。协调者逐条核实、回派与验收，建议处置和无 blocker 是收敛条件，不能用固定轮数代替。rebase 后 patch-id 相同仅证明补丁等价，不证明基线、依赖、产物或环境等价；旧证据保留原 head 标签，核实际差异后重验受影响行为，当前 checks 仍须属于当前 head。

呈报当前 head 的审查结论、行为证据、required checks、依赖与风险。用户要求审查时，由执行审查者按审查规范发布意见，不另索发布许可；approve/merge 各需明确指令，不因「出货」一词自动获得权限。用户合入后盯最新主线门禁，批次窗口与清理完全遵守项目约定；CI 红保留重试载体。

真实应用证据用项目里的应用驱动流程启动与取证；性能结论先过项目的基准流程，不以编译通过或单次计时替代。
