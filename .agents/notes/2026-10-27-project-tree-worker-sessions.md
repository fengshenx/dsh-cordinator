# 项目树只列 worker 会话

**状态**：implemented（2026-10-27）
**范围**：`src/host/projects/session-index.js`、`src/host/projects/service.js`、`src/client/project-panel.js`、`src/client/project-section.js`、`tests/project-session-index.test.js`（删除 `src/client/workspace-hiding.js` 与 `tests/workspace-hiding.test.js`）

## 背景

两条需求：「新建项目后直接展示，不要注册流程」与「项目下只展示 worker 会话」。

原先的行为：左栏「项目」区块点「加项目」要先选目录、再起名、点「注册」才建；项目树展开后按目录列出该目录下的**所有**会话（协调者会话与用户手动开的会话混在一起）；插件注册的项目工作区在渲染层被整棵藏起来。

## 决策

**项目树的归组判据是「子代理会话 + 目录相同」两条件**。会话头 `origin: 'subagent'` 是宿主给子代理会话的正式标记（`packages/core/session/src/types.ts:95-130`），协调者派出的 worker 就是这一类；再叠上会话 cwd 与项目目录的 realpath 精确相等。缺了 `origin` 这一半，用户的会话会被算成项目会话；缺了目录这一半，判据就太宽。

依据不止类型声明：宿主的官方工作区树用同一个判据筛会话——`packages/client/ui-workspace/src/client/tree.ts` 的 `sessionVisible()` 第一行就是 `if (session.origin === 'subagent') return false`。本仓的项目树与官方树口径一致，同一条 worker 会话不会在两边各出现一次。

- 协调者会话的入口在项目行上（点项目行打开它），本来就不该在子列表里重复一次。
- 用户在项目目录里手动开的会话属于用户自己，不属于「这个项目有哪些 worker」这个问题。

**取消插件工作区的隐藏**。隐藏与「只列 worker」是连着的：项目工作区一旦被整棵藏掉，用户在项目目录里手动开的会话既不在项目树里（它不是 worker）、又被官方树藏起来，两边都无处可寻。取消后它们回到官方树——项目目录是一个普通工作区，里面是用户自己的会话；项目的协调者会话仍由渲染层排除，worker 会话由宿主自己滤掉，都不在那里重复出现。代价是官方左栏里多出项目目录这一项；项目目录里除协调者外没有别的会话时这一项是空分组（分组行在、展开后无内容）。

**加项目直接建好，但失败要有出口**。选完目录即建项目并出现在列表里，名字默认取目录名，要改用行上的「重命名」；原来的「起名 + 点注册」两道手续删掉。目录选择器不可用时，提示改为「请在终端里用 add_project 建项目」。两个例外必须有出路：

- **目录名当不了项目名**（选到根目录、目录名超过 200 字）时退回一个能改名字的输入框。直接提交只会换回一条没有出口的报错——项目没建成，列表里就没有那一行，行上的「重命名」也不存在。
- **同名目录**（`/work/a/repo` 与 `/work/b/repo`）在落盘时自动加序号（`repo`、`repo-2`…），查重与写入在同一个串行链里完成。重名不破坏数据（id 与目录都不同），但列表里两个一模一样的名字没法指认。
- **改名撞名报错，不偷偷加序号**。建项的自动避让只建立了「名字唯一」的一半；改名同样能撞上，不查重的话列表里会重新出现两个一模一样的名字。这里选择报错让用户改：他明明打了一个名字，被改成「X-2」比看到「已被占用」更意外。

## 边界

- 排除集只含项目的协调者会话；worker 会话由宿主的官方树自己滤掉，放进去也找不到元素。用户手动开的会话留在官方工作区树里。
- 子目录里的 worker 不算项目下的 worker（realpath 精确相等）。
- 项目记录里的 `workspaceId` 仍只写插件自己注册的工作区（「从 dsh 移除工作区」入口据此出现），与隐藏与否无关。
- `workspace-hiding.js` 整套机制随隐藏取消而删除，未使用的代码不留。

## 取证

- **单元测试**：`npm run check` 289 例全绿。新增用例覆盖：非 worker 会话不归属项目（`origin` 缺失但 cwd 相同的协调者会话与用户会话）、目录名能当或当不了项目名、同名项目自动加序号（含并发同名与跳过已占用的序号）、改名撞名报错且改成自己当前的名字不报错。
- **回归有效性**：撤掉 `uniqueProjectName` 的查重后「同名项目落盘时自动加序号」失败，还原后通过；撤掉 `update` 里的改名查重后「改名撞上已有项目名时报错」失败，还原后通过。
- **真实实例（mock LLM，隔离 DSH_HOME）**：项目区块显示项目名、无「注册」按钮；展开项目行列出的全是 worker 会话（`MOCK-WORKER-TASK 收工即可`），协调者会话不在其中；官方工作区树里用户手动开的会话仍在；console 无报错。
