# 查卡工具的列表摘要与分页口径

**状态**：implemented（P5，2026-10-27）
**范围**：`src/host/cards/card-list-view.js`、`src/host/tools/cards.js`、`tests/card-list-view.test.js`、`tests/cards-tools.test.js`

## 背景

列表全量输出的问题在本仓同样存在：项目卡累积后，全量列表输出从约 3,160 字符涨到 98,652 字符，检查点 JSON 占 72.6%；旧列表不渲染 links，模型无法区分「没渲染」和「字段为空」，于是误判「项目卡没有产物链接」——实际 130/134 张卡都有链接。

本仓的 `list_cards` 原先是「按编号升序返回全部未归档卡，模型视图只有 `#编号 标题（状态）」一行一条」。卡少时够用，卡一多就把模型上下文冲垮，也让协调者看不出「这张卡到底有没有产物」。

## 决策

**模型出口与客户端出口分离**。工具 `execute` 返回全量卡片加解析后的 `query`，分页与状态过滤只发生在 `output.render` 给模型的文本上；`output.presentationMeta` 始终投全量。

理由是客户端看板的唯一取数通道就是 `presentationMeta`：看板要按全量卡片重建视图，被裁掉就是丢卡（宿主事件窗口是分页的，一次全量投影必须代表全量）。而 `presentationMeta` 是**同步**函数，拿不到 store，没法在它内部重新过滤——所以过滤只能落在 `render` 上，让两个出口各自拿自己需要的那份数据。

**默认只列 `active`**，`status` 枚举扩为 `active | done | archived | all`，删掉 `includeArchived`。本仓尚未发布，不留重复参数的兼容层。默认从「全部未归档」改成「仅 active」是可见行为变更：协调者查卡默认看不到已完成的卡，要看得显式说 `status: 'done'`。

**列表只渲染可观测事实**。每张卡一行标题（含编号、状态、cardId、revision、更新时间）加三条存在性标记（`spec: 有/无`、`links: <标签摘要> 或 无`、`checkpoint: 有/无`）与槽位行；规格与检查点全文只在传 `cardId` 的单卡查询里出现。链接只给标签（至多 5 个、单个标签至多 32 字符），地址与用途留给单卡查询。

**存在性标记无条件成行**。省略「有/无」会被模型读成「没有」——旧列表不渲染 links 时，模型因此误判项目卡没有产物链接。空集合显式写「无」，与「未渲染」区分开。

**`revision` 在列表里可见**。协调者的工作流是「查卡读 revision → 改卡带 `expectedRevision`」，revision 不出现在列表里，这条工作流就断了。

**输出有 6000 字符预算**，逐卡累加，超出按卡截断并给续页位置；还没到预算但本页没放完时也给续页位置。预算取 `LIST_MAX_CHARS = 6000`。截断发生在卡片边界，不切半张卡。

**首行不报本页张数**。首行只写「共 N 张」（总数是事实），本页显示了几张由尾注说（`本页显示 11/20 张`）。首行若按 `limit` 写「本页 20 张」，预算截断后会与尾注的「只显示 11 张」自相矛盾——同一句输出里两个数打架，模型不知道信哪个。

**空页与翻过头是两句话**。「项目当前没有 active 卡（active 0 · done 0 · archived 0）」是事实；「offset 超出范围：status=active 共 N 张，请从 offset=0 重新翻页」是操作提示。混成一句会让协调者以为卡被删了。

**参数非法直接报错**：状态不在枚举内、`limit` 非正整数、`offset` 为负、`cardId` 为空串，都抛错而不是静默收敛。`limit` 超过上限 100 时收敛到 100（不是报错）——要一页看更多是合理请求，只是有上限。

## 边界

- `presentationMeta` 投的是**全量**卡片，不受 `status` / `limit` / `offset` 影响。这是有意的：看板是全量视图，分页是给模型看的。
- 列表顺序按 `updatedAt` 倒序，不按编号。协调者关心的是正在动的卡，历史卡不能把当前卡挤出第一页。
- 单卡查询忽略 `status` 与分页参数（`cardId` 命中即给完整事实）。同传 `cardId` 与冲突的 `status` 时按 `cardId` 查那张卡——单卡查询要给事实，不能因为状态过滤而说「卡不存在」。
- **首张卡无条件渲染**：预算只拦第二张往后。极端情况下（单卡标题 8000 字符）输出会超出 6000 字符上限。取舍是「宁可超预算也要给第一张」——一张都不给，模型无法判断项目里有没有卡。
- 列表里的槽位行只渲染卡片自己声明的绑定，本仓工具侧拿不到宿主运行态，所以不显示信号灯档位。

## 证据

- 单测 264 例全绿（新增 `tests/card-list-view.test.js` 15 例：参数解析与非法值、limit 上限收敛、默认只列 active 与全量计数、倒序与翻页、单卡忽略分页、三项存在性成行、链接只给标签、规格与检查点全文只在单卡出现、空页与翻过头是两句话、状态尾注、续页位置、预算截断、单卡完整事实、首卡查询忽略 status 与分页、首行不报本页张数）。
- 真实实例（隔离 mock profile + mock LLM）：协调者实际调用 `list_cards` 成功，模型侧读到列表摘要文本；客户端看板仍显示全部卡片（全量投影未被分页裁剪）。
- 真实实例复验（审查意见修复后）：模型侧读到的首行是「卡片快照（status=all，共 5 张）：」——不再出现「本页 N 张」，与尾注显示数不再自相矛盾。
