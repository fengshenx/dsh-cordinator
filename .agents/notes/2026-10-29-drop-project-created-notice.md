# 建项目成功不再弹提示

**状态**：implemented（2026-10-29）
**范围**：`src/client/project-panel.js`、`README.md`

## 背景

用户反馈：新建项目后，左栏「项目」区块底部会多出一行「已建项目「dsh-coordinator」。」。这行字挤在项目行与「Workspaces」之间，看起来像一条残留或错误提示，实际是建项成功后的回执（`setNotice` 写进区块尾部的 `.dsh-coordinator-project-notice`）。

## 决策

**建项成功不弹提示，新项目行本身就是回执**。左栏「项目」区块在两个入口上都删掉 `setNotice(...)`：

- `startAdd`（点「加项目」选完目录即建好）
- `confirmNaming`（目录名当不了项目名时退回的改名框里确认）

理由：建项是左栏内的一步操作，结果直接落在同一视线上——新行出现在「项目」区块里，用户不需要再读一句「已建项目…」才知道成功。原来那行提示还带着三重副作用：在窄栏里换行、把「Workspaces」挤下去、与真正的失败提示共用同一个位置，让人分不清刚才那一行是成功还是出错。

`createdName()` 只为这条提示存在（重名时宿主自动加序号，提示要说建成的那个名字），随之删除——实际名字从此只在项目行上体现。

**新行本身就是回执这件事有前提：行得看得见**。项目行只在整个列表展开时渲染（`project-section.js`），而「加项目」按钮在 header 里、收起状态照样可点。所以两个入口在 `refresh()` 之后都补一句 `setListExpanded(true)`：建完自动展开，回执不因折叠而消失。没有退回「收起时补一条成功提示」——提示位与失败提示共用一个容器，正是这次要删掉的那种混淆，展开列表是同一句「行就是回执」的延伸。

## 边界

- 失败提示全部保留：`建项目失败：…`、`目录选择器不可用：请在终端里用 add_project 建项目。`、改名框里的 `建项目失败：…`。
- 空态提示保留：「还没有项目。加一个即在它的目录里建好协调者会话。」——没有项目行可看时，它是唯一的出路说明。
- 列表收起不是「不弹提示」的例外：收起时建项照样零提示，但列表会自动展开，新行当场出现。折叠状态由用户点的标题决定，建项成功后收起状态失去意义（用户刚建了一个要看的东西）。
- 「已从 dsh 移除项目…」等其他成功提示不在本次范围：它们对应的是「行消失了」这种反向变化，提示补的是消失后的确认。

## 验证

真机读数走隔离实例（`DSH_HOME=/tmp/...`，不碰用户 `.dev/home` 的数据），无头浏览器里只把「目录选择器返回哪个目录」换成固定路径（宿主原生目录面板无法在无头环境里作答），建项、刷新、渲染、提示全部走真实代码：

- 修复前构建：点「加项目」后 `.dsh-coordinator-project-notice` 文本为 `已建项目「probe-dir」。`，项目行同时出现。
- 修复后构建：同一流程后没有该提示元素，项目行从 1 行变 2 行（`probe-dir`、`probe-dir-2`）。
- `lib/client.js` 里 `已建项目` 出现次数：修复前 2，修复后 0；`npm run check` 433 个用例全绿。

收起态的真机读数（先点标题收起列表，再点「加项目」选目录，读 `aria-expanded`、项目行与提示元素）：

| 读数 | 本项目改动前 | 本项目改动后 |
|---|---|---|
| 建项后 `aria-expanded` | `false`（仍收起） | `true`（自动展开） |
| 建项后项目行 | `[]`（看不到） | `["probe-dir"]` |
| 建项后提示元素 | `[]` | `[]` |
| 手动展开后项目行 | `["probe-dir", "probe-dir-2"]`（这行是刚才悄悄建出来的） | —— |

改前的读数正是评审指出的回退：界面毫无变化，用户会以为没建成再点一次，宿主按重名规则多建一个 `-2`。
