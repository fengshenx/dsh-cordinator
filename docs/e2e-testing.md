# 浏览器侧取证的执行规范

`npm run check` 只覆盖纯函数与落盘逻辑。圆点档位、折叠水位、浮层位置这类东西，只有把应用真跑起来才能证明。过去几轮取证靠临场发挥：反复重启实例、手写数据文件、为了看一个字段临时往仓库代码里塞日志，结论难以复现，也难说清哪条断言真正守住了行为。这份说明把流程固定下来。

## 分层与判据

| 层 | 命令 | 证明什么 | 证明不了什么 |
|---|---|---|---|
| 纯函数与落盘 | `npm run check` | 投影、状态归一、去重、串行与并发 | 浏览器里实际渲染成什么 |
| 浏览器取证 | 本说明 | DOM 的真实 class 与计算样式、落盘 JSON、真实会话状态 | 不替代单测；不证明未覆盖的分支 |

能在纯函数层断言的，必须先落到 `tests/`。浏览器取证只补「非真机不可见」的那部分，不拿来替代单测。

## 一次取证的固定顺序

1. **先写断言**。能进单测的先写单测并看它变红，再改实现。
2. **起隔离实例**。`DSH_HOME` 指独立目录，端口独占，不与常用实例抢。token 每次启动都变，从启动日志用正则取出写入文件，**只打印长度**，不打印全文。
3. **场景用标记驱动**。标记写在用户输入里（`MOCK-<场景名>`），本地 mock provider 按标记返回固定的工具调用序列。一个标记只表达一个场景，标记名与用例名对得上。
4. **断言外部世界**。读 DOM 的 class、`getComputedStyle` 的具体属性、磁盘上的 JSON。不读 agent 的自述文本，不拿页面里的推理文字当证据。
5. **回归有效性双向验证**。撤掉修复 → 断言必须变红 → 还原 → 变绿。绿了但撤掉修复也绿，说明断言没守住任何东西。结果写进 PR。
6. **清理**。kill 端口、删探针脚本、截图与临时数据不入库。

## 状态类断言的三条硬规矩

- **造状态用 seed，不要在 UI 上逼近**。圆点档位这类瞬时态，靠反复重启、反复改配置去凑，永远对不齐；把目标状态直接写进数据文件，让界面去读。
- **headless 下弹不出的原生控件如实标注**。目录选择器、系统文件对话框在无头浏览器里拿不到结果，这类分支只能靠单测 + 样式注入核验，PR 里写明「未 GUI 实测」，不要含糊成「已验证」。
- **标识符必须来自本次运行**。会话 id、worker id 从本次日志或数据文件里取，不硬编码上一轮残留的值——上一轮的值往往已经失效，会把你带到错误的结论上。

## 失败诊断

- **先查有没有被静默吞掉的错误**。本仓出过「圆点不亮」查不出原因的情况，根因是三处空 `catch`：保留会话失败、订阅就绪失败，全都吞掉，界面上只剩一个空心圈。失败必须报告，且同一目标只报一次，不随每帧同步重复刷。
- **区分「数据没到」与「渲染错了」**。把快照的字段名打出来，确认 `running` 这类字段是否存在；字段不在，问题在数据层，不在渲染层。
- **一次性日志优于每帧日志**。首次读数打一条就够，高频刷新会把控制台淹掉，反而看不见。

## 禁止

- 用脚本（`python3` 之类）改仓库代码做文本替换。临时回退用 `git stash` 或编辑器；探针脚本放 `/tmp`，验证完删掉。
- 为了取证在仓库代码里留 `[probe]` 前缀的临时日志。要么把它转成正式的失败报告，要么删掉。
- 真实调用付费 LLM API。运行时验证一律用本地 mock provider。
- 把截图、临时数据文件当成提交内容。
